Canonical Confirmation:
- `emit-batch` derives WAITING_FOR_CONFIRMATION carriers.
- `confirm-batch` accepts only matching APPROVED_HANDOFF_MODE / WAITING_FOR_CONFIRMATION Session and Checkpoint carriers.
- predecessor confirmed_action_ids is empty.
- predecessor unconfirmed_action_ids equals the complete Runtime Context Action set.
- exact operator token is required.
- resulting Session and Checkpoint are derived as BUILD_ACTIVE.
- Checkpoint sequence increments and parent_checkpoint_id binds the predecessor.
- confirmation-receipt.json, checkpoint.json, session-state.json, and confirmation-result.json publish atomically or not at all.
- Receipt binds the resulting Checkpoint ID, sequence and parent, plus Session, Package, Candidate, Context, Batch, Action IDs, Action body digests and token.

Checkpoint sequence:
- sequence == 1 requires parent_checkpoint_id == null.
- sequence > 1 requires a non-empty parent_checkpoint_id.

Evidence:
- source.status must be the exact string verified.
- required_action_execution requires source.action_id in the active Context Action set.
- assertion.subject_ref and source.subject_ref must equal source.action_id.
- generic builder-output subjects cannot prove Action execution.
- rejected Evidence contributes no claim class or Action coverage.

Real Completion rereads selected source bytes, rederives Runtime Context, validates the exact confirmed Batch and Receipt checkpoint identity, verifies Evidence, then atomically derives COMPLETED carriers.

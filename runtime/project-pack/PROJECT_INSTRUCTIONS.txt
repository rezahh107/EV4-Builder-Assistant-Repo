Mode arguments:
- project-gate requires Receipt and Builder Input.
- direct-ce requires CE source wrapper and forbids Builder Input.
- manual-builder-input forbids source artifact and requires Builder Input.

real-intake copies exact bytes into the Run, derives Context, run_id, session_id, initial Checkpoint and Session, and publishes the complete Run atomically. Initial Checkpoint is BUILD_ACTIVE, sequence 1, null parent, empty confirmed Actions and complete unconfirmed Actions.

After Intake, only the Run directory is accepted. Original source paths are never read again. New source content requires a new Run.

Before emit-batch, fully rederive Context from the internal snapshot and compare Package, Candidate, Batch, Action IDs, Action-body digests and Confirmation binding. Active blockers include Session unresolved Evidence, Checkpoint blockers and unresolved assertions. Any blocker prevents Action emission.

emit-batch atomically derives WAITING_FOR_CONFIRMATION. confirm-batch accepts only that exact emitted State, exact Batch/Actions/digests, exact token and zero blockers. It atomically publishes Confirmation Receipt, Confirmation Result, Checkpoint and Session. Caller-authored Receipt or confirmed arrays have no authority.

attach-evidence reads external Evidence once, requires exact source.status == "verified", validates claim, subject, Session, Package and Action binding and byte-preserves Evidence inside the Run. required_action_execution must use the exact active Action ID as source.action_id, assertion.subject_ref and source.subject_ref.

real-completion fully rederives Context from the internal snapshot, validates current State, sequence, Confirmation, exact confirmed Batch and Actions, internal Evidence and zero blockers, then derives terminal Session, Checkpoint, Completion Status and Gate atomically.
